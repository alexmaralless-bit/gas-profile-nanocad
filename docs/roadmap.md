# Roadmap разработки плагина GasProfile

## Цель

Сделать инженерный плагин nanoCAD для построения продольного профиля подземного газопровода по 2D-трассе, топографическим отметкам и плановой ситуации с оформлением по ГОСТ 21.710-2021.

Основной рабочий цикл:

```text
выбрать трассу -> выбрать одну отметочную точку -> собрать точки поверхности
-> построить TIN -> построить фактическую землю -> построить проектную трубу
-> вручную поправить трубу -> пересчитать таблицу
-> добавить футляры/пересечения на плане -> обновить профиль и развернутый план
-> проверить оформление и расчет
```

## Текущее состояние

MVP расчетной части уже работает:

- C# проект `GasProfile.NanoCad` создан и собирается через `build.ps1`;
- DLL загружается в nanoCAD через `NETLOAD`;
- реализованы команды диагностики, TIN, чернового профиля, пересчета, футляров и ситуации;
- `GASPROF_DRAW_DRAFT` строит фактическую землю, редактируемую проектную трубу, таблицу и развернутый план;
- `GREC` / `GASPROF_RECALC_PROFILE` пересчитывает таблицу по отредактированной проектной трубе;
- профиль хранит связь с трассой, поверхностью и трубой через XData;
- футляры распознаются по плановым блокам и могут актуализировать пикетаж;
- масштаб по умолчанию: 1:500 по горизонтали и 1:100 по вертикали;
- труба/таблица уже считают дно траншеи с учетом наружного диаметра и песчаной подушки 100 мм.

Главный активный фокус сейчас: **доведение UI профиля, таблицы и развернутого плана до ГОСТ**.

Детальная спецификация этой фазы хранится в:

```text
docs/gost-ui-implementation-spec.md
```

## Принцип разработки

Дальше идем короткими проверяемыми сессиями:

1. Каждая сессия должна давать загружаемую DLL.
2. Каждая сессия должна улучшать один конкретный аспект профиля.
3. После каждой сессии проверяем на демонстрационном чертеже (в репозиторий не входит) визуально в nanoCAD.
4. Расчетную математику не ломаем ради косметики.
5. Если появляется спор между roadmap и UI-спекой, детальная UI-спека имеет приоритет для текущей фазы.

## Этап 7. Футляры и плановая ситуация

Статус: частично выполнено.

Команды:

```text
GCAS
GASPROF_ADD_CASING
GCEDIT
GASPROF_EDIT_CASING
GASPROF_ADD_SITUATION
GASPROF_RECALC_CASINGS
GASPROF_DUMP_BLOCK
```

Реализовано:

- распознавание футляров по effective block name и атрибутам;
- чтение геометрии планового блока;
- расчет `START_CHAINAGE`, `END_CHAINAGE`, `CENTER_CHAINAGE`, пикетов и длины;
- `GEOM_SIGNATURE` для отслеживания устаревших атрибутов;
- автоматическая актуализация футляров перед использованием.
- отдельная команда `GCAS` / `GASPROF_ADD_CASING` вставляет протяженный плановый блок футляра `GASPROF_CASING_PLAN`;
- блок футляра ориентируется по трассе, получает видимый атрибут `DN`, скрытые атрибуты пикетажа и начальную `GEOM_SIGNATURE`;
- футляр можно двигать/масштабировать штатными средствами nanoCAD, после чего `GASPROF_RECALC_CASINGS` или `GREC` обновляют пикетаж.
- команда `GCEDIT` / `GASPROF_EDIT_CASING` меняет подпись `DN` и длину сгенерированного футляра без ручного открытия атрибутов;
- для библиотечных футляров `GCEDIT` меняет `DN`, а геометрию оставляет штатным ручкам динамического блока;
- после редактирования `GCEDIT` очищает `GEOM_SIGNATURE`, чтобы `GVAL` и `GREC` не доверяли старому пикетажу.
- футляр получил структурные атрибуты: `CASING_MATERIAL`, `HAS_CONTROL_TUBE`, `CONTROL_TUBE_CHAINAGE`, `CONTROL_TUBE_PICKET`, `NORM_OFFSET_START`, `NORM_OFFSET_END`;
- `GCAS` запрашивает материал, наличие контрольной трубки и нормативные отступы при вставке нового футляра;
- `GCEDIT` редактирует структурные параметры футляра вместе с `DN` и длиной;
- `GASPROF_RECALC_CASINGS` актуализирует пикетаж, длину, контрольную трубку и добавляет дефолтные структурные параметры старым футлярам;
- `GVAL` предупреждает о футлярах без структурных параметров.
- добавлена общая модель `CasingData`, которая читает DN, материал, контрольную трубку, нормативные отступы, начало/конец, длину и пикеты из атрибутов футляра;
- подпись футляра в развернутом плане для `GASPROF_DRAW_DRAFT` и `GREC` теперь строится из `CasingData`: DN, материал и длина.
- `GASPROF_RECALC_CASINGS` и `GVAL` переведены на `CasingData` для чтения длины, пикетов и структурных параметров;
- профильная отрисовка футляра теперь учитывает `HAS_CONTROL_TUBE`: при `NO` контрольная трубка на профиле не рисуется.
- контрольная трубка футляра в графике профиля и развернутом плане рисуется по `CONTROL_TUBE_CHAINAGE`, а не по фиксированной доле длины.
- `GCEDIT` редактирует смещение контрольной трубки от начала футляра и обновляет `CONTROL_TUBE_CHAINAGE` / `CONTROL_TUBE_PICKET`.
- нормативные отступы `NORM_OFFSET_START` / `NORM_OFFSET_END` выводятся короткой подписью футляра в развернутом плане;
- `GVAL` предупреждает, если длина футляра меньше суммы нормативных отступов или контрольная трубка выходит за границы футляра;
- профиль и развернутый план показывают футляр с общей графической логикой и подписями, ближе к ГОСТ.
- `SymbolRenderer` теперь рисует общий профильный знак ситуации для футляров и пересечений из одного места в `GASPROF_DRAW_DRAFT` и `GREC`.
- одиночные пересечения на профиле и точечные отметки развернутого плана также переведены на `SymbolRenderer`.
- добавлена общая модель `SituationSymbol` для условных знаков: начало/конец трассы, УП, ПК, пересечение и футляр.
- устаревший `ProfileSituationItem` удален, профильная ситуация в `GREC` теперь строится сразу на `SituationSymbol`.

Осталось:

- проверить UX нового блока футляра в nanoCAD и решить, достаточно ли scale-grip сценария или нужен настоящий динамический блок;
- довести оставшиеся редкие условные знаки до `SymbolRenderer` и убрать устаревшие DTO ситуации.

## Этап 8. Условная графика

Статус: запланировано после базового ГОСТ UI.

Цель: вынести отображение знаков в отдельный генератор.

Кандидат на сервис:

```text
SymbolRenderer
```

Режимы:

```text
ProfileGraph
UnfoldedPlan
PlanBlock
```

Знаки:

- дорога;
- канава;
- кабель;
- трубопровод пересекаемый;
- футляр;
- контрольная трубка;
- угол поворота;
- элемент газопровода.

Критерий готовности:

- условные знаки генерируются кодом;
- внешний вид знака меняется в одном месте;
- данные знака передаются через `SituationSymbol`, а не через набор разрозненных строк и координат;
- динамические блоки не обязательны для MVP, но библиотечные блоки могут использоваться как источник параметров.

## Этап 9. Настройки и хранение состояния

Статус: частично выполнено.

Текущее состояние:

- базовые параметры профиля хранятся в XData проектной трубы `GASPROF_PIPE`;
- актуальная версия XData: `GASPROF_PIPE_PROFILE_V5`;
- сохранены точка вставки, база, масштабы, длина трассы, session id, handle трассы, слой поверхности, подписи, диаметр трубы и песчаная подушка;
- команда `GSET` / `GASPROF_SETTINGS` позволяет изменить наружный диаметр, толщину песчаной подушки, подпись трубы и подпись основания;
- старые профили `V1`-`V4` читаются с дефолтами;
- `GREC` использует сохраненные настройки при пересчете таблицы.

Что добавить:

- ID всех объектов профиля;
- глубина до верха трубы;
- режим отбора станций таблицы;
- минимальный зазор между подписями;
- настройки весов линий и текстовых высот;
- имя профиля.
- редактирование масштабов с геометрическим преобразованием уже построенного профиля.

Команда:

```text
GSET
GASPROF_SETTINGS
```

Критерий готовности:

- профиль можно перестроить без повторного выбора всех объектов;
- пользователь может изменить параметры профиля без пересборки DLL;
- настройки переживают `GREC`.

## Этап 10. Проверки и диагностика

Статус: частично выполнено, UI-проверки MVP реализованы.

Команды:

```text
GVAL
GASPROF_VALIDATE
GASPROF_CHECK
```

Проверять:

- трасса не выбрана или удалена;
- проектная линия трубы не найдена;
- связь с поверхностью устарела;
- трасса выходит за TIN;
- слишком мало топоточек;
- дубли топоточек;
- длинные ребра TIN;
- футляр с нулевой/отрицательной длиной;
- устаревшие атрибуты футляра;
- труба выше земли;
- глубина меньше заданного минимума;
- слишком плотные подписи таблицы;
- слишком короткие сегменты уклонов;
- неподдерживаемые типы объектов.

Реализовано в UI-сессии:

- отчет `GVAL` с отдельным счетчиком ошибок и предупреждений;
- проверка сигнатур трассы, поверхности, проектной трубы и футляров;
- предупреждения по плотным табличным колонкам;
- предупреждения по коротким сегментам уклонов;
- предупреждения по слишком большим уклонам;
- проверка базовых настроек профиля: диаметр, песчаная подушка, подписи трубы и основания;
- сообщения с пикетажем проблемного места, где он известен.

Критерий готовности:

- пользователь получает понятный отчет до построения или пересчета;
- ошибки не приводят к битому профилю;
- предупреждения помогают понять, что надо исправить вручную.
