# Концепция плагина продольного профиля газопровода для nanoCAD

## Назначение

Плагин предназначен для быстрого построения инженерного продольного профиля подземного газопровода в nanoCAD по существующей 2D-трассе и топографическим отметкам чертежа.

Первая версия должна решать практическую задачу:

- взять 2D-полилинию трассы газопровода;
- собрать точки фактической поверхности земли по слою выбранной отметочной точки;
- построить триангуляционную модель поверхности;
- определить отметки земли по трассе в характерных точках и на пересечениях трассы с ребрами треугольников;
- построить продольный профиль и таблицу под ним в формате, близком к требованиям СПДС для наружных сетей газоснабжения.

Основной нормативный ориентир: ГОСТ 21.710-2021 "Система проектной документации для строительства. Правила выполнения рабочей документации наружных сетей газоснабжения". Старый ГОСТ 21.610-85 заменен ГОСТ 21.710-2021.

## Исходные данные

### Трасса газопровода

Трасса задается 2D-полилинией nanoCAD.

Требования к трассе:

- объект: `Polyline` или совместимый DWG-объект полилинии;
- координаты вершин: `X`, `Y`;
- отметка `Z` у трассы не используется;
- пикетаж считается от первой вершины по порядку полилинии;
- дуговые сегменты на первом этапе лучше не поддерживать либо аппроксимировать короткими прямыми сегментами.

### Топографические отметки

Пользователь выбирает одну отметочную точку на чертеже. По выбранному объекту плагин определяет слой и далее автоматически выбирает все подобные объекты на этом же слое.

Поддерживаемый MVP-вариант:

- отметочный объект имеет координаты `X`, `Y`, `Z`;
- `Z` объекта является отметкой земли;
- текст рядом с точкой используется только как дополнительная проверка, но не как основной источник данных.

Возможные типы объектов:

- `DBPoint`;
- блок с точкой вставки, где `Position.Z` является отметкой;
- 3D-точка или другой точечный объект, если nanoCAD API позволяет надежно получить `Point3d`.

В первой версии лучше ограничиться одним типом отметочных объектов. Если на чертеже отметки представлены блоками, нужно явно поддержать именно блоки, так как в топосъемках это часто встречается.

## Нормативный состав профиля

По ГОСТ 21.710-2021 продольный профиль газопровода выполняют как развертку по оси газопровода.

На профиле должны быть предусмотрены:

- фактическая поверхность земли;
- проектная поверхность земли, если она есть;
- проектируемый газопровод;
- пересекаемые автомобильные дороги, железные дороги, кюветы, инженерные коммуникации и сооружения, влияющие на прокладку;
- отметки верха трубы для подземного газопровода;
- глубина траншеи от фактической и проектной поверхности;
- футляры с диаметром, длиной и привязкой;
- характерные точки трассы.

Для таблицы под профилем подземного газопровода нужно предусмотреть строки:

- `Отметка земли проектная, м`;
- `Отметка земли фактическая, м`;
- `Отметка дна траншеи, м`;
- `Отметка верха трубы, м`;
- `Глубина траншеи, м`;
- `Обозначение трубы и тип изоляции`;
- `Уклон, промилле; длина, м`;
- `Расстояние, м`;
- `Основание`.

В MVP можно строить только строки:

- `Отметка земли фактическая, м`;
- `Отметка дна траншеи, м`;
- `Отметка верха трубы, м`;
- `Глубина траншеи, м`;
- `Обозначение трубы и тип изоляции`;
- `Основание`;
- `Уклон, промилле; длина, м`;
- `Расстояние, м`;
- `Пикетаж`;
- `Развернутый план`.

Остальные строки оставить как настраиваемые или пустые.

## Локальная база ГОСТ

ГОСТ сохранен и разложен в локальную базу:

- ГОСТ 21.710-2021 в репозиторий не включен (авторские права); документ нужно иметь под рукой отдельно;
- ключевые требования стандарта описаны ниже в этом документе.

Дополнительная проектная документация:

- концепция библиотеки блоков: `docs/gas-profile-block-library.md`.
- предложения по разработке после разбора связанных ГОСТов: `docs/gas-profile-development-proposals.md`.


Практические выводы из рисунка Б.1:

- строку `Пикет` стоит добавить в таблицу сразу, хотя она является дополнительной строкой к форме;
- строка `Развернутый план` должна быть обязательной для нашего плагина;
- в развернутом плане показываются ось трассы, УП, угол поворота, длина участка, футляр, колодец/элемент газопровода;
- футляр в развернутом плане подписывается диаметром, толщиной стенки и длиной;
- проектная линия трубы на графике идет как основная толстая линия;
- пересекаемые коммуникации на графике профиля показаны вертикальными очертаниями с подписью и отметками;
- строка `Уклон, промилле; длина, м` оформляется наклонной линией по участку, над линией указывается уклон, под/рядом длина участка;
- в примере рядом с профилем указаны масштабы по горизонтали и вертикали;
- отметки в таблице повернуты вертикально, чтобы не раздувать ширину граф.

## Предлагаемый стек

Основной стек:

- C#;
- .NET API nanoCAD;
- загрузка сборки через `NETLOAD`;
- стандартные DWG-примитивы без собственных CAD-объектов.

Почему так:

- задача сводится к чтению объектов чертежа, расчету геометрии и генерации обычных линий, полилиний, текста и таблиц;
- не требуется создавать новые интеллектуальные сущности DWG;
- C# проще для быстрой инженерной разработки, чем C++/NRX;
- результат остается обычным чертежом, который можно редактировать вручную.

Отдельные библиотеки:

- для Delaunay-триангуляции можно использовать легкую C#-библиотеку либо реализовать Bowyer-Watson внутри плагина;
- для MVP допустима своя реализация Delaunay, если число точек умеренное;
- для больших топосъемок лучше использовать готовую проверенную библиотеку, чтобы не тратить время на отладку геометрических крайних случаев.

## Команды плагина

### `GASPROF_BUILD`

Основная команда построения профиля.

Порядок работы:

1. Запросить выбор 2D-полилинии трассы.
2. Запросить выбор одной отметочной точки.
3. Определить слой выбранной точки.
4. Собрать все подобные точечные объекты с этого слоя.
5. Построить TIN по `X`, `Y`, `Z`.
6. Найти расчетные точки профиля.
7. Рассчитать отметки фактической земли.
8. Запросить точку вставки профиля.
9. Построить график профиля и таблицу.

При первичном построении плагин также должен построить проектную линию газопровода по умолчанию:

- линия строится на постоянной проектной глубине от фактической поверхности земли;
- линия соответствует отметке верха трубы;
- пользователь после построения может вручную редактировать вершины проектной линии на профиле;
- таблица после ручного редактирования обновляется отдельной командой пересчета.

### `GASPROF_RECALC`

Команда пересчета ранее построенного профиля.

Порядок работы:

1. Найти профиль по выбранному объекту профиля или по имени профиля.
2. Прочитать текущую проектную полилинию верха трубы.
3. Прочитать расчетные точки, пересечения и системные блоки ситуации.
4. Пересчитать отметки верха трубы в расчетных пикетах.
5. Пересчитать глубину заложения.
6. Пересчитать отметки дна траншеи, если задан наружный диаметр и основание.
7. Пересчитать уклоны и длины участков проектной линии.
8. Обновить таблицу профиля и графические подписи.

Важный принцип: пользователь редактирует проектную линию трубы как обычную DWG-полилинию, а таблица является производной от этой линии.

### `GASPROF_ADD_CROSSING_PLAN`

Команда добавления пересекаемой коммуникации или ситуации на плане.

Пользователь вставляет системный блок на плане, а не на профиле. Это правильнее, потому что исходное положение пересечения должно жить в координатах трассы.

Минимальный сценарий:

1. Запросить точку вставки блока на плане.
2. Запросить тип пересечения.
3. Запросить отметку верха/низа или глубину.
4. Вставить системный блок малого диаметра с атрибутами.
5. Найти ближайшую точку на трассе или пересечение с трассой.
6. Рассчитать пикетаж.
7. При `GASPROF_RECALC` отобразить это пересечение на профиле и в развернутом плане.

Для MVP блок можно показывать на плане простым маленьким кругом, но обязательно хранить данные в атрибутах.

### `GASPROF_IMPORT_CROSSINGS`

Команда автоматического сбора системных блоков ситуации с плана.

Порядок работы:

1. Пользователь выбирает один блок ситуации.
2. Плагин определяет имя блока и слой.
3. Плагин собирает все блоки такого же имени или все блоки с системным признаком `GASPROF_CROSSING`.
4. Для каждого блока рассчитывает пикетаж по трассе.
5. Блоки привязываются к текущему профилю.

Это позволит сначала расставить все пересечения на плане, а потом одной командой перенести их в профиль.

### `GASPROF_SETTINGS`

Команда настроек.

Параметры:

- горизонтальный масштаб профиля: `1:200`, `1:500`, `1:1000`, `1:2000`;
- вертикальный масштаб: `1:50`, `1:100`;
- базовая отметка профиля;
- глубина заложения или отметка верха трубы;
- диаметр трубы;
- слой профиля;
- слой фактической земли;
- слой проектируемого газопровода;
- стиль текста;
- высота текста;
- точность отметок;
- шаг дополнительных расчетных точек, если нужен.
- высота строки `Развернутый план`;
- режим показа точек TIN в таблице;
- максимальное расстояние от системного блока до трассы для автоматической привязки;
- список слоев или имен блоков, относящихся к ситуации.

### `GASPROF_CHECK`

Диагностическая команда.

Проверяет:

- сколько найдено точек поверхности;
- есть ли дубли точек по `X`, `Y`;
- попадает ли трасса внутрь области триангуляции;
- есть ли участки трассы, где отметку нельзя интерполировать;
- минимальную и максимальную отметку поверхности;
- длину трассы.

## Алгоритм расчета

### 1. Сбор точек поверхности

После выбора одной отметочной точки:

1. Получить тип объекта.
2. Получить слой объекта.
3. Найти в текущем пространстве все объекты того же типа на том же слое.
4. Для каждого объекта получить координаты `X`, `Y`, `Z`.
5. Отбросить объекты без корректной отметки `Z`.
6. Удалить дубли по `X`, `Y`.

Если рядом с точкой есть текст с отметкой, его можно использовать как контроль:

- найти ближайший текст в радиусе настройки;
- распарсить число;
- сравнить с `Z` точки;
- при расхождении больше допуска добавить предупреждение.

В MVP текст можно не читать.

### 2. Построение TIN

TIN строится Delaunay-триангуляцией по координатам `X`, `Y`.

Каждая вершина треугольника хранит:

- `X`;
- `Y`;
- `Z`;
- ссылку на исходный объект чертежа, если нужно для диагностики.

После построения нужно удалить треугольники:

- с почти нулевой площадью;
- с очень длинными ребрами, если задан максимальный допустимый размер ребра;
- с некорректными вершинами.

Максимальная длина ребра полезна, чтобы профиль не интерполировался через пустые зоны топосъемки.

### 3. Расчетные точки профиля

Расчетные точки делятся на обязательные и дополнительные.

Обязательные:

- начало трассы;
- конец трассы;
- все вершины 2D-полилинии трассы;
- точки пересечения трассы с ребрами TIN;
- пересечения с дорогами, кюветами, коммуникациями, если пользователь выбрал соответствующие объекты.

Дополнительные:

- регулярный шаг по пикетажу, например каждые 10 или 20 м;
- точки изменения проектного уклона трубы;
- точки начала и конца футляров;
- точки установки арматуры, коверов, колодцев.

Для первой версии критически важно добавлять точки пересечения трассы с ребрами треугольников. Тогда линия фактической земли на профиле будет корректно повторять кусочно-линейную TIN-поверхность.

### 4. Интерполяция отметки земли

Для каждой расчетной точки трассы `P(X, Y)`:

1. Найти треугольник TIN, внутри которого лежит точка.
2. Взять три вершины треугольника `A`, `B`, `C`.
3. Вычислить плоскость треугольника.
4. Найти `Z` точки на этой плоскости.

Формула плоскости:

```text
Z = aX + bY + c
```

Альтернативно можно использовать барицентрические координаты:

```text
Zp = w1 * Za + w2 * Zb + w3 * Zc
```

Барицентрический способ удобен для проверки попадания точки в треугольник.

Если точка трассы лежит вне всех треугольников:

- не экстраполировать молча;
- отметить участок как ошибочный;
- в профиле поставить разрыв или предупреждение;
- в `GASPROF_CHECK` вывести список проблемных пикетов.

### 5. Пикетаж

Пикетаж считается по длине 2D-трассы.

Для каждой расчетной точки хранить:

- расстояние от начала трассы;
- номер сегмента полилинии;
- локальный параметр на сегменте;
- координаты `X`, `Y`;
- отметку фактической земли;
- тип точки.

Формат пикетажа:

```text
ПК0+00,00
ПК1+23,45
```

Можно дополнительно хранить расстояние в метрах как число.

## Построение графики в DWG

### Слои

Рекомендуемые слои:

- `GASPROF_AXIS` - оси и сетка;
- `GASPROF_GROUND_EXIST` - фактическая поверхность земли;
- `GASPROF_PIPE` - проектируемый газопровод;
- `GASPROF_TABLE` - таблица;
- `GASPROF_TEXT` - текст;
- `GASPROF_MARKS` - вертикальные линии характерных точек;
- `GASPROF_WARNINGS` - проблемные места.

### Координатное преобразование

Для точки профиля:

```text
Xprofile = Xinsert + chainage / horizontalScaleFactor
Yprofile = Yinsert + (Z - baseElevation) / verticalScaleFactor
```

Практически удобнее считать не через знаменатель масштаба напрямую, а через коэффициенты чертежа:

```text
Xprofile = Xinsert + chainage * Kx
Yprofile = Yinsert + (Z - baseElevation) * Ky
```

Где `Kx` и `Ky` задаются настройками масштаба профиля.

### Линия фактической земли

Строится полилинией по расчетным точкам, отсортированным по пикетажу.

Стиль:

- сплошная тонкая линия;
- слой `GASPROF_GROUND_EXIST`.

### Линия трубы

В MVP можно задать одним из способов:

1. постоянная глубина заложения от фактической земли;
2. постоянная отметка верха трубы на участке;
3. проектная ломаная по заданным точкам.

Для инженерного чернового варианта быстрее начать с постоянной глубины:

```text
ZpipeTop = ZgroundExisting - coverDepth
```

При этом нужно понимать, что такой вариант не является полноценным проектированием уклонов и не заменяет проектное решение.

### Таблица

Под профилем строится табличная часть.

В MVP таблицу проще выполнять обычными линиями и текстом, а не объектом `Table`, потому что так легче контролировать внешний вид по СПДС.

Столбцы соответствуют расчетным точкам или участкам между точками.

Минимальные строки:

- пикетаж;
- расстояние между точками;
- уклон и длина проектного участка;
- отметка земли фактическая;
- отметка дна траншеи;
- отметка верха трубы;
- глубина заложения;
- обозначение трубы и тип изоляции;
- основание;
- развернутый план.

Ориентировочные высоты строк по форме 1:

- строки отметок и глубины: 15 мм;
- строка `Обозначение трубы и тип изоляции`: 15 мм;
- строка `Основание`: 10 мм;
- строка `Уклон, промилле; длина, м`: 10 мм;
- строка `Расстояние, м`: 10 мм;
- строка `Развернутый план`: 20 мм.

Строку `Пикет` можно добавлять как дополнительную строку между `Расстояние, м` и `Развернутый план`, как в примере Б.1.

### Развернутый план

В таблице под профилем нужно предусмотреть отдельную строку или полосу `Развернутый план`.

Это не обычный план в координатах `X/Y`, а развертка трассы по пикетажу. Горизонтальная координата совпадает с профилем:

```text
Xprofile = Xinsert + chainage * Kx
```

В этой полосе нужно показывать:

- ось газопровода как прямую горизонтальную линию;
- углы поворота трассы;
- числовые значения углов поворота, если их не показывают на отдельном плане;
- дороги, проезды, кюветы и другие пересечения;
- системные блоки коммуникаций;
- футляры;
- колодцы, коверы, КИП, ЭХЗ и другие элементы газопровода;
- привязки к пикетам.

Для MVP развернутый план можно выполнять упрощенно:

- одна горизонтальная линия оси трассы;
- вертикальные штрихи в местах характерных точек;
- подписи `УП1`, `УП2`, `дорога`, `В1`, `КЛ`, `К1`;
- маленькие условные знаки пересечений;
- углы поворота текстом над/под линией.

Главное: все объекты в развернутом плане должны быть привязаны не к координатам листа, а к пикетажу. Тогда при пересчете они правильно переедут вместе с профилем.

### Редактируемая проектная линия газопровода

Проектируемый газопровод на профиле хранится как обычная полилиния на слое `GASPROF_PIPE_DESIGN`.

Смысл координат:

- `X` полилинии на листе соответствует пикетажу;
- `Y` полилинии на листе соответствует проектной отметке верха трубы;
- вершины полилинии являются точками изменения проектной отметки или уклона.

После первичного построения плагин создает эту линию на равной глубине от фактической земли:

```text
ZpipeTop = ZgroundExisting - coverDepth
```

Дальше пользователь может вручную:

- поднимать или опускать вершины;
- добавлять вершины;
- удалять лишние вершины;
- выравнивать участки.

Команда `GASPROF_RECALC` должна читать фактическую геометрию этой полилинии и пересчитывать от нее таблицу.

Это дает нормальный инженерный цикл:

```text
построил профиль -> посмотрел -> поправил трубу -> пересчитал таблицу
```

### Системные блоки ситуации на плане

Пересекаемые коммуникации и элементы ситуации лучше хранить на плане системными блоками.

Минимальный блок можно сделать визуально простым:

- маленький круг;
- точка вставки является расчетным положением пересечения;
- атрибуты хранят инженерные данные.

В MVP не нужно делать динамические блоки ядром решения. Надежнее использовать простые блоки с атрибутами, а графику профиля и строки `Развернутый план` строить кодом. Динамические блоки можно добавить позже как слой ручного оформления.

Рекомендуемое имя блока:

```text
GASPROF_CROSSING_POINT
```

Рекомендуемые атрибуты:

```text
GP_TYPE              тип: ROAD, DITCH, WATER, SEWER, CABLE, HEAT, GAS, CASE, OTHER
GP_NAME              отображаемое имя: В1, К1, КЛ-0.4, дорога, кювет
GP_ELEVATION_TOP     отметка верха пересекаемого объекта
GP_ELEVATION_BOTTOM  отметка низа пересекаемого объекта
GP_DIAMETER          диаметр или габарит
GP_WIDTH             ширина дороги, кювета или сооружения
GP_MATERIAL          материал, если нужен
GP_NOTE              примечание
GP_CHAINAGE          расчетный пикетаж, заполняется плагином
GP_PROFILE_ID        идентификатор профиля, если блок уже привязан
```

Почему блок на плане лучше, чем блок на профиле:

- он остается в реальных координатах трассы;
- его можно проверить на плане;
- профиль можно перестроить, а пересечение не потеряется;
- при изменении трассы можно пересчитать пикетаж;
- один и тот же блок можно показать и в развернутом плане, и на графике профиля.

На профиле плагин строит уже производное изображение этого блока:

- вертикальную линию в точке пикетажа;
- условный контур коммуникации по отметкам и габаритам;
- подпись;
- запись в таблице и/или в развернутом плане.

Производные объекты на профиле можно удалять и создавать заново при `GASPROF_RECALC`.

## Характерные точки

Типы точек:

- `START` - начало трассы;
- `END` - конец трассы;
- `VERTEX` - угол/вершина трассы;
- `TIN_EDGE` - пересечение трассы с ребром треугольника;
- `ROAD_CROSSING` - пересечение дороги;
- `UTILITY_CROSSING` - пересечение коммуникации;
- `CASE_START` - начало футляра;
- `CASE_END` - конец футляра;
- `MANUAL` - ручная добавленная точка.

На профиле желательно подписывать только значимые точки, а не все точки `TIN_EDGE`, иначе чертеж будет перегружен.

Точки `TIN_EDGE` нужны для геометрической точности линии земли, но в таблице их можно скрывать настройкой.

## MVP

Первая рабочая версия:

- выбор 2D-полилинии трассы;
- выбор одной отметочной точки;
- автосбор всех точек того же типа и слоя;
- построение Delaunay TIN;
- расчет точек профиля: начало, конец, вершины трассы, пересечения с ребрами TIN;
- построение фактической земли;
- построение линии трубы по постоянной глубине;
- ручное редактирование проектной линии трубы как обычной полилинии;
- пересчет таблицы после ручного изменения проектной линии;
- строка `Развернутый план` в упрощенном виде;
- системный блок пересечения на плане в виде малого круга с атрибутами;
- простая таблица под профилем;
- диагностика участков вне TIN.

Не включать в MVP:

- полноценное проектирование уклонов;
- автоматическое распознавание дорог по условным знакам;
- чтение всех возможных видов топографических блоков;
- оформление всех строк ГОСТ-таблицы;
- автоматическое проектирование футляров;
- инженерно-геологические колонки;
- грунтовые воды;
- спецификацию.

## Вторая очередь

После MVP:

- поддержка выбора слоев дорог и коммуникаций;
- автоматическое добавление пересечений дорог в таблицу;
- ручной редактор проектной линии трубы;
- расчет уклонов по участкам;
- футляры на пересечениях дорог;
- более подробные блоки пересечений с условной графикой по типам сетей;
- автоматическое обновление развернутого плана при изменении трассы;
- разбиение длинного профиля на листы;
- сохранение настроек в DWG;
- экспорт расчетной таблицы в CSV/XLSX;
- проверка расхождений между `Z` точки и текстовой отметкой;
- поддержка блоков отметок с атрибутами;
- шаблон оформления под конкретный стандарт предприятия.

## Риски и допущения

- Если топоточки лежат только вдоль трассы и не покрывают область вокруг нее, TIN может давать плохие треугольники. Нужен контроль максимальной длины ребра.
- Если трасса выходит за контур триангуляции, отметки нельзя корректно получать интерполяцией.
- Если в одном слое есть лишние точки не из топосъемки, они испортят TIN. Нужен фильтр по типу объекта и, возможно, по диапазону отметок.
- Если отметочные точки представлены блоками, нужно заранее определить, где хранится отметка: в `Z` вставки, атрибуте или тексте рядом.
- Если полилиния содержит дуги, их нужно аппроксимировать, иначе расчет пикетажа и пересечений будет неполным.
- Если профиль нужен строго для выпуска рабочей документации, MVP должен пройти ручную инженерную проверку и дооформление.

## Главное проектное решение

Плагин должен считать фактическую поверхность не только в вершинах трассы и на пересечениях дорог, а во всех точках пересечения трассы с ребрами TIN. Это делает профиль земли математически согласованным с построенной триангуляционной поверхностью.

Иначе профиль будет выглядеть гладко или упрощенно, но не будет точно соответствовать исходной топосъемке.
