# Предложения по разработке плагина после разбора связанных ГОСТов

## Главный вывод

Плагин нужно проектировать не как библиотеку DWG-блоков, а как расчетно-графический генератор профиля.

Исходные данные должны храниться в простых объектах nanoCAD:

- 2D-полилиния трассы;
- точки поверхности;
- простые системные блоки с атрибутами на плане;
- редактируемая проектная полилиния верха трубы на профиле.

Графика профиля, таблицы и строки `Развернутый план` должна генерироваться кодом.

Это лучше соответствует ГОСТам: они разрешают условные графические обозначения, упрощенные изображения, буквенно-цифровые обозначения и пояснения на чертеже.

## Нормативное разделение по задачам

### ГОСТ 21.710-2021

Использовать как главный стандарт профиля газопровода.

Из него берем:

- состав профиля;
- таблицу под профилем;
- строку `Развернутый план`;
- отметки фактической/проектной земли;
- отметку верха трубы;
- глубину траншеи;
- футляры;
- пересечения дорог, кюветов, коммуникаций и сооружений;
- марки `ГК`, `КП`, `УП`, `Н`.

### ГОСТ 21.206-2012

Использовать для логики трубопроводов.

Для плагина важно:

- условное обозначение трубопровода состоит из графики и буквенно-цифрового/цифрового обозначения;
- трубопроводы на схемах изображают одной линией;
- на чертежах трубопроводы можно изображать условно или упрощенно;
- если диаметр в масштабе 2 мм и более, трубопровод изображают двумя линиями;
- проектируемые видимые трубопроводы - сплошная толстая основная;
- существующие трубопроводы - сплошная тонкая;
- обозначения можно ставить на выноске, над линией или в разрыве линии.

Решение для MVP:

- проектный газопровод на профиле строить одной толстой линией по отметке верха трубы;
- пересекаемые трубопроводы показывать упрощенным контуром или одной линией с подписью;
- двухлинейное отображение трубы сделать настройкой второй очереди.

### ГОСТ 21.205-2016

Использовать для:

- арматуры и элементов трубопроводных систем;
- буквенно-цифровых обозначений сетей.

Важные обозначения:

```text
В   водоснабжение
К   канализация / водоотведение
Т   теплосеть
Г   газопровод
```

Газопроводы:

```text
Г1  низкое давление до 0,1 МПа
Г2  среднее давление св. 0,1 до 0,3 МПа включ.
Г3  высокое давление св. 0,3 до 0,6 МПа включ.
Г4  высокое давление св. 0,6 МПа
Г5  продувочный
Г6  на разрежение
Г7  газопровод / трубопровод безопасности
```

Решение для MVP:

- в настройках профиля хранить код проектируемого газопровода `PIPE_CODE`, например `Г1`, `Г2`, `Г3`;
- в блоках пересечений хранить `GP_NAME`, например `В1`, `К1`, `К2`, `Т1`, `Г3`, `W1`, `V1`;
- `GP_TYPE` использовать для логики, `GP_NAME` использовать для подписи.

### ГОСТ 21.204-2020

Использовать для генплана, сетей, транспортных сооружений и водоотвода.

Для плагина важно:

- проектируемые здания, сооружения, сети и транспортные устройства показываются условными или упрощенными изображениями;
- обозначения выполняют линиями по ГОСТ 2.303;
- обозначения, не вошедшие в стандарт, надо пояснять на чертеже;
- трубопроводную, кабельную или воздушную сеть наносят одной линией по оси трассы;
- буквенно-цифровые обозначения сетей ставят в разрывах линии и у характерных точек;
- сети в одной траншее допускается показывать одной линией с перечислением сетей на выноске;
- для сетей допускаются цвета, но в черно-белой документации все должно читаться без цвета;
- есть отдельные обозначения водоотводных сооружений: лотки, канавы, кюветы, водопропускные трубы, дренаж.

Решение для MVP:

- для пересекаемых сетей на плане достаточно системного блока;
- на профиле сети показывать упрощенно: ось/контур/подпись/отметки;
- в `Развернутом плане` показывать пересечение коротким штрихом с `GP_NAME`;
- кювет/канава должен быть отдельным типом `DITCH`, а не просто `OTHER`;
- водопропускная труба и дренаж должны быть отдельными типами второй очереди.

### ГОСТ 21.207-2013

Использовать для пересечений автомобильных дорог.

Для плагина важно:

- ширину дороги на плане показывают в масштабе, но не менее 2 мм;
- если в масштабе ширина менее 2 мм, проектируемую дорогу показывают сплошной толстой основной линией;
- есть обозначения пересечений, съездов, примыканий;
- элементы продольного профиля дороги используют логику: наклонная линия, уклон над линией, длина под линией.

Решение для MVP:

- `ROAD` должен иметь `GP_WIDTH`;
- на профиле дорогу показывать двумя вертикальными границами и подписью;
- в `Развернутом плане` дорогу показывать как отрезок ширины по пикетажу или штрих с подписью, если ширина не задана;
- детальные знаки дорог не делать в первой версии.

### ГОСТ 21.210-2014

Использовать для кабелей и электрообъектов.

Для плагина важно:

- изображения проводок и электрооборудования могут быть заменены общими изображениями;
- в этом случае на выноске, в разрыве линии или в контуре приводят позиции или буквенно-цифровые обозначения.

Решение для MVP:

- кабельные пересечения показывать общим знаком и подписью `КЛ`, `W`, `V` или пользовательским `GP_NAME`;
- не делать библиотеку электрических условных знаков в первой версии;
- для кабелей обязательны `GP_NAME`, `GP_ELEVATION_TOP` или глубина/отметка.

### ГОСТ Р 21.302-2021

Использовать только во второй очереди.

Нужно, если добавляем:

- скважины;
- уровень подземных вод;
- грунтовые колонки;
- литологию на профиле.

Решение:

- не включать геологию в MVP;
- зарезервировать типы `BOREHOLE`, `GROUNDWATER`, `SOIL_LAYER`;
- не смешивать геологию с блоками пересечений коммуникаций.

### ГОСТ 2.303-68

Использовать для стандартизации линий.

Решение:

- сделать слой/стиль линий через отдельный `LineStyleRegistry`;
- не хардкодить толщины в каждой функции рисования;
- задать роли линий: `ThickMain`, `Thin`, `DashedThin`, `DashDotThin`, `ConstructionThin`.

## Предлагаемая архитектура

### 1. Расчетное ядро

Модули:

```text
Geometry
  Route2D
  Chainage
  TinSurface
  Intersections

Profile
  ProfileModel
  ProfilePoint
  DesignPipe
  TrenchCalculator
  SlopeCalculator

Standards
  SymbolType
  LineRole
  NetworkCode
  GostProfileRows
```

Расчетное ядро не должно зависеть от nanoCAD API. Это позволит тестировать TIN, пикетаж, уклоны и таблицу отдельно.

### 2. CAD-адаптер

Модули:

```text
Cad
  CadSelectionService
  CadPointCollector
  CadBlockReader
  CadBlockWriter
  CadProfileDrawer
  CadTableDrawer
  CadUnfoldedPlanDrawer
  CadXDataStore
```

Этот слой читает и пишет DWG.

### 3. Генераторы графики

Отдельные генераторы:

```text
GroundProfileRenderer
DesignPipeRenderer
CrossingProfileRenderer
ProfileTableRenderer
UnfoldedPlanRenderer
SymbolRenderer
```

`SymbolRenderer` принимает тип объекта и рисует его примитивами, без динамических блоков.

## Модель системного блока на плане

Оставить три основных блока:

```text
GASPROF_CROSSING_POINT
GASPROF_PIPE_NODE
GASPROF_CASE
```

Но расширить атрибуты.

### Общие атрибуты

```text
GP_ID
GP_PROFILE_ID
GP_TYPE
GP_NAME
GP_SOURCE
GP_CHAINAGE
GP_OFFSET
GP_NOTE
```

### Отметки

```text
GP_ELEVATION_TOP
GP_ELEVATION_AXIS
GP_ELEVATION_BOTTOM
GP_DEPTH
```

Правило:

- если задана отметка, используем отметку;
- если задана глубина, считаем отметку от фактической земли;
- если данных не хватает, показываем пересечение без высотного контура и выдаем предупреждение.

### Габариты

```text
GP_DIAMETER
GP_WIDTH
GP_HEIGHT
GP_WALL
GP_MATERIAL
```

### Футляр

```text
GP_CHAINAGE_START
GP_CHAINAGE_END
GP_LENGTH
GP_CASE_DIAMETER
GP_CASE_WALL
```

## Генерация развернутого плана

Развернутый план должен быть отдельным рендерером, не частью таблицы отметок.

Вход:

- трасса;
- вершины трассы;
- системные блоки пересечений;
- футляры;
- элементы газопровода;
- настройки масштаба и высоты строки.

Выход:

- ось трассы;
- `УП1`, `УП2` на вершинах;
- значения углов поворота;
- футляры;
- пересечения;
- подписи;
- длины участков, если включено.

### Угол поворота

Для каждой внутренней вершины трассы:

```text
angle = угол между предыдущим и следующим сегментом
```

В развернутом плане:

- знак угла;
- подпись `УПn`;
- значение угла, кроме 90 градусов, если включено правило ГОСТ 21.710.

### Футляр

Генерировать кодом:

```text
ось       ----------------------------
футляр       [================]
подпись       Футляр Ø325x5; L=23,00
```

Если задан центр и длина:

```text
start = center - length / 2
end = center + length / 2
```

Если заданы начало и конец, длина считается автоматически.

### Дорога

Если есть `GP_WIDTH`:

```text
start = chainage - width / 2
end = chainage + width / 2
```

В развернутом плане:

- две границы дороги;
- короткая полоса/отрезок;
- подпись `дорога`, материал или имя.

Если ширина не задана:

- один штрих в пикетаже;
- подпись.

### Кювет

Кювет показывать отдельным знаком:

- короткий V-образный знак или две наклонные линии;
- подпись `кювет`;
- при наличии отметок выводить их на графике профиля.

### Кабель

Кабель показывать:

- коротким вертикальным штрихом;
- подписью `КЛ`, `W...`, `V...` или `GP_NAME`;
- на графике профиля - тонкой вертикальной линией/контуром с отметкой.

## Таблица профиля

Таблицу делать не `Table`-объектом, а линиями и текстом.

Причины:

- проще повторить форму ГОСТ;
- проще повернуть отметки вертикально;
- проще перестраивать отдельные строки;
- проще управлять шириной столбцов по пикетажу.

Строки MVP:

```text
Отметка земли проектная, м
Отметка земли фактическая, м
Отметка дна траншеи, м
Отметка верха трубы, м
Глубина траншеи, м
Обозначение трубы и тип изоляции
Основание
Уклон, промилле; длина, м
Расстояние, м
Пикет
Развернутый план
```

## Проверки качества

Команда `GASPROF_CHECK` должна проверять:

- трасса внутри TIN;
- дубли топоточек;
- слишком длинные ребра TIN;
- пустые отметки у пересечений;
- пересечения без пикетажа;
- футляры с отрицательной/нулевой длиной;
- труба выше земли;
- глубина меньше заданного минимума;
- конфликт подписи/типа сети;
- невозможность пересчитать таблицу из-за удаленной проектной линии.

## Порядок реализации

### Этап 1. Геометрия и земля

- чтение 2D-трассы;
- чтение точек по слою;
- TIN;
- отметки фактической земли;
- расчетные точки по TIN-ребрам.

### Этап 2. Профиль и труба

- график фактической земли;
- проектная труба на постоянной глубине;
- редактируемая полилиния верха трубы;
- пересчет таблицы от измененной трубы.

### Этап 3. Таблица и развернутый план

- форма таблицы;
- строка пикетов;
- строка расстояний;
- строка уклонов;
- строка `Развернутый план`;
- УП и углы поворота.

### Этап 4. Ситуация

- системные блоки пересечений на плане;
- импорт блоков;
- дороги;
- кюветы;
- кабели;
- трубопроводы;
- футляры.

### Этап 5. Оформление

- слои;
- толщины линий;
- стили текста;
- шаблон профиля;
- предупреждения и диагностика.

### Этап 6. Геология и расширенные знаки

- скважины;
- грунтовые воды;
- грунты;
- детальные знаки дорог/электрики/сетей.

## Что не делать в первой версии

- не делать динамические блоки ядром данных;
- не делать полный редактор условных знаков;
- не делать автоматическое распознавание всех объектов топосъемки;
- не делать геологию;
- не делать листование длинных профилей;
- не делать строгую экспертизу по всем нормативам.

## Конкретное решение по условным обозначениям

Сделать `SymbolRenderer`, который рисует условные знаки примитивами по типу:

```text
DrawRoad(...)
DrawDitch(...)
DrawPipeCrossing(...)
DrawCable(...)
DrawCase(...)
DrawTurn(...)
DrawPipeNode(...)
```

Каждый метод должен иметь два режима:

```text
ProfileGraph      график профиля
UnfoldedPlan      строка развернутого плана
```

Блок на плане остается только носителем данных.

Так мы не зависим от динамических блоков, но можем получить аккуратную ГОСТ-подобную графику.
